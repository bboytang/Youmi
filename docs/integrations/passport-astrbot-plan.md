# Passport 与 AstrBot 语音及跨设备衔接计划

状态：实施中；尚未接通或验收。Passport 通过现有语音服务识别语音，交给 AstrBot 原生 Agent 和适用工具，回复经现有校验及 TTS 播放。QQ 与设备保持独立授权，共用 Youmi 人格、记忆和情绪。

## 实施

1. 固定线上与仓库基线，保留工作区现有改动，核实设备、授权、模型和插件版本。
2. 为设备增加 AstrBot 平台事件及服务端桥接，使用绑定设备会话、回合和授权的短期凭证；复用设备的 MCP 会话，停止断线或撤销后的输出，不重放不确定的工具调用。AstrBot 不可用时提示并等待。
3. 统一回合完成路径，防止设备原有处理与 AstrBot 重复提交回复、情绪、事件和记忆；维持现有权限及上下文校验。
4. 增加同一授权智能体的共享已完成回合和摘要，保存最多 7 天；最近原文优先，超预算才摘要，摘要随来源到期或删除而失效。独立进行中的回合完成后按服务端提交顺序共享；去重 AstrBot 本地历史。
5. 首次导入最近 7 天中可确认来源、交付及隐私状态的 QQ 对话，无法确认的跳过。实现共享记录的暂停、恢复、清除和隐私限制；不自动删除 QQ 原有记录、长期记忆或独立笔记。
6. 验证适用于设备的插件、MCP 与媒体回退。保留现有角色、音色和配置；逐项记录不适用或未验证能力。
7. 对精确变更提交运行 GitHub Actions 服务、授权、集成和相关兼容检查；审查差异和迁移、部署候选并验证回退，最后进行真实 QQ 与设备双向续聊、语音、打断、工具和隐私验收。

## 验收

双向立即切换能接续已完成话题；上下文有界，7 天清理和摘要失效有效；同时聊天不混淆进行中回合。检查授权撤销、重复请求、超时、断线、工具不确定性和失败时无重复效果。设备实测 Agent 工具、MCP、连续语音和播放；QQ 原功能回归。记录确切 SHA、CI 链接、生产及实机结果；不得把 fixture 或构建冒称实机通过。

进度见 [工作记录](passport-astrbot-worklog.md) 和 [交接](passport-astrbot-handoff.md)。

## 当前实施边界

- 已有默认关闭的设备事件、实体设备授权、Agent 回复与设备 MCP 候选，以及 V19 共享历史、摘要和隐私控制；这些改动仅经过隔离测试，尚未上线。
- 近期上下文取对端最多 12 轮、12 KB；超出时仅对紧接其前最多 8 轮、24 KB 生成摘要，生成失败时退回近期原文，超过该范围的记录不保证进入本轮上下文。保留期限不是承诺把七天全部内容送入模型。
- 首次导入：当前旧记录缺少足以证明与完成账本逐条关联及禁记状态的证据，先跳过，不能按内容或时间猜测；后续仅在发现可靠证据时导入可确认的片段。
- 余下依次为组合测试、精确提交及 GitHub Actions、部署前迁移和回退验证、受控启用与实机验收；在这些条件具备前保持开关关闭。
