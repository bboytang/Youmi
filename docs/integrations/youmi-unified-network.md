# Youmi 统一联网插件与出站网络实施记录

状态：开发与隔离验证中，尚未将透明分流切换到生产。用户要求只有一个 AstrBot 联网操作入口，允许后台保留代理和浏览器服务；不设置网站白名单或黑名单，不在 `/xiaoxiao` 内写文件。

## 已查明的问题

原代理和 Browserless 使用 `network_mode: service:astrbot`。隔离实验确认 AstrBot 容器重启或重建后，它们可能保留旧网络空间，造成代理或渲染失联。生产网页插件也曾被修改为使用临时 31989 中继，其进程随容器重启丢失。

当前已对生产做兼容修复：原 Xray 分流代理在保留 31987 的同时提供 31989；该入口使用与原认证上游完全相同的路由和出站，不改动私人目录中的中继脚本。用户已通过 QQ 实测 BBC 网页渲染正常。当前旧网络空间依赖尚未消除；维护时仍须按现有交接重建伴随容器。

## 目标与约束

- 将搜索、读取和浏览器渲染统一由现有 `astrbot_plugin_youmi_web` 提供；保留 QQ 授权，并为 Passport 绑定当前已授权的设备回合。
- 保留现有 Xray 的 `geosite:cn`/`geoip:cn` 直连及默认 VPN 出站，不写死网站清单。容器内部和私有地址直连，避免影响 QQ、Youmi 桥接及数据库。
- 对未读取环境代理的程序使用独立网络空间内的 TCP/UDP 透明代理；代理自身的出站使用独立标记避免循环。代理故障时，外网连接不得静默绕过代理。
- 用稳定网络空间承载 AstrBot、Xray 和 Browserless，保留原服务发现别名、端口、卷、密钥、配置与 Passport 挂载；应用重启或重建不应令伴随服务失联。
- 不能假设 IPv6、DNS、容器或宿主机重启已经安全：当前候选仅覆盖 IPv4，检测到 IPv6 默认路由必须拒绝部署；DNS 污染、容器启动顺序、宿主机重启和回退均需在隔离环境及上线前确认。
- 不复制或输出生产节点凭据和用户内容。`xray_config.py` 在生产本机生成仅供运行的 0600 配置，不覆盖原始配置。

## 验证进度

- 独立无外网网络实测：TCP REDIRECT 和 UDP TPROXY 使用不同监听入口时均能工作；代理停止时外网 TCP 失败、内部回环仍可访问。错误命名空间和重复安装会被拒绝。
- 用临时隔离容器验证生产路由的拷贝：国外测试站走 VPN 并返回 200，国内测试站走直连并返回 200；现有 VPN 的 UDP DNS 请求得到有效响应。未输出生产节点配置。
- 独立实验确认稳定网络空间让应用容器重启和重建后仍与代理共享网络；生产 Compose 候选已解析并核对，除网络空间、依赖及端口迁移外原配置保持一致，尚未应用。
- 跨设备网页工具授权候选要求设备会话仍在线，且回合标识与服务端确认一致；现有 QQ 私聊/主动消息授权规则保持。相关测试和生产运行验证仍需完成。

## 未完成的发布步骤

完成规则安装器的隔离回滚测试、DNS 与 IPv6 验证、稳定网络空间启动顺序及故障恢复设计；将统一插件和部署代码提交后，在 GitHub Actions 对精确提交运行测试。完成 Compose 配置差异、实际模型/QQ/设备授权、网页渲染、国内外路由、重启及回退验证后，再受控切换生产。用户之前要求不新增生产数据库备份，本任务不得擅自创建。

## 本次隔离验证补充

- 用户确认通过 QQ 调用 BBC 渲染正常；她的两个临时中继进程未继续运行，私人目录文件未修改。原渲染代码使用的 31989 兼容入口现在由持久 Xray 服务提供，路由与认证上游一致。
- TCP 与 UDP 使用独立透明监听器；单监听器混合模式曾导致 TCP 失败，已拒绝。只监听回环地址的双入口在独立网络中均通过，内部回环在代理关闭时仍可访问，外部 TCP 在代理关闭时失败，代理启动后 TCP 和 UDP 成功。
- 使用真实生产路由配置在临时容器中验证：手工绕过代理变量的国内和国外 HTTPS 均可访问；模拟 VPN 失效时国外访问失败、国内站点仍返回 200、DeepSeek 能到达认证响应。给 HTTPS 一个故意错误的目的 IP，按 SNI 域名仍成功访问；外部 UDP DNS 通过代理可得到响应。这不保证所有协议均可从 DNS 错误中恢复。
- 用通过 GitHub 检查的独立守护镜像验证启动前安装规则，规则就绪与代理监听都满足后才启动应用。隔离 Compose 中，应用重启与重建均保持网络空间；直接重启网络守护容器会使子服务脱节，恢复器已在独立环境重接代理、浏览器及应用，并在 Compose 文件改变时拒绝覆盖。
- 已对生产网页插件当前授权函数做 AST 指纹比对，在内存中准备了仅替换该函数并新增状态工具的补丁，验证其余用户方法保持不变；尚未写入线上插件。候选 Passport 网页授权已在真实 AstrBot `PassportEvent` 类上验证当前回合可通过、回合不匹配会拒绝。

## DNS 和启动门禁的隔离结果

- 在独立容器中使用仅监听回环的 DNS 服务：无代理时内部 Docker 服务名仍能解析、公开域名返回失败而不直连；启动现有 VPN 后，公开域名 DNS 查询可通过透明 UDP 获得答复。另一个共享网络容器挂载候选 `resolv.conf` 后，默认解析内部服务与公开域名均成功。没有记录查询名称或应答内容。
- 后续隔离测试将 A/AAAA 查询交给 Xray 按现有 geosite 分类选择 DNS：模拟 VPN 不可用时，中国域名通过国内 DNS 成功解析，国外域名未直连。其他查询类型仍走代理；该行为与地理数据库的分类结果有关。
- 网络守护进程和应用、浏览器均有启动门禁：规则就绪且代理监听后才运行；浏览器门禁在真实 Browserless 镜像的无网络临时容器中验证。当前生产无 IPv6 出网路由；候选发现任何非本地 IPv6 路由会拒绝启动，不能声称已支持 IPv6。
- 独立实验对安装器注入规则失败，已写入的专用链和策略路由全部回滚；稳定网络容器被直接重启后，恢复器能重接依赖，修改 Compose 文件后恢复器拒绝运行。生产候选配置只增网络、门禁和 DNS 所需挂载，其它服务及原有挂载、端口已逐项比对，尚未上线。
