# 情感系统实施方案

状态：已获用户确认，实施中。日期：2026-10-25。

## 目标与身份

新增独立「情感系统」管理页。以现有服务端验证的 `user:<user_id>:agent:<agent_id>` 为隔离键：同一智能体的所有绑定设备、App、QQ共享配置和状态；不同智能体严格分开。前端不得自行指定 owner。通用模块不绑定 Youmi 名称。

## 完整维度

- 基础情绪：快乐/喜悦、悲伤、愤怒、恐惧、焦虑、惊讶、厌恶、平静/放松。
- 复杂情感：爱、依恋、亲密感、同情、共情、慈悲、感激、欣赏、自豪、自尊、自信、羞耻、内疚、尴尬、嫉妒、羡慕、失望、孤独、希望、意义感、归属感、安全感、信任感、责任感、道德感、审美感、好奇心、兴趣。
- 需要：感官满足、生理需要、安全、亲密、成就、被认可；身体相关需要标为角色模拟。
- 性格：温柔度、亲近度、小脾气及现有角色配置。
- 调节原则：承认感受、区分需要和冲动、情境匹配与强度控制、不伤害、受挫恢复与求助、为选择负责。原则的表达和执行倾向可调，授权、事实真实性和禁止伤害底线不可关闭。

各维度提供启用、当前值、基线、上下限、固定/自动/临时锁定模式、敏感度、单轮最大变化、表达强度和恢复半衰期（可停用恢复）。界面使用0–100。默认性格和原则固定，其他维度自动；新增维度克制初始化。

## 页面与接口

主导航与智能体卡片提供入口，支持智能体切换。标签：总览、性格基线、基础情绪、复杂情感、需要与欲望、自我调节、变化记录。草稿保存、状态调整与长期配置分开；保存失败不显示成功；有版本冲突提示。

Manager代理 `/agent/{agentId}/affect-system`，复用登录、HTTPS、所有者前后复核与现有语音HTTP服务。动作：status、configure、adjust、reset、history。新配置、状态、回合去重及历史使用原SQLite增量迁移。历史最长90天/每智能体10000条，无额外聊天全文。

## 对话与兼容

读取状态→按时间恢复→一次有界模型评价→后端限幅计算→临时上下文→完整回合成功后幂等提交。失败保留旧状态；多设备以版本拒绝过时写。聊天设置指令不作为情绪刺激。App/设备和AstrBot复用计算模块。新智能体默认关闭；旧智能体启用时继承既有性格和情绪，新增项使用默认配置。保留旧API和旧数据，避免双份状态成为两个权威。

## 交付顺序和验收

1. 维度目录、计算、迁移及管理接口：验证隔离、全维度配置、锁定/恢复/限幅、冲突、历史与兼容。
2. 对话与QQ接入：验证临时状态、成功提交一次、超时/发送失败/重启/并发。
3. 管理页面：验证全维度可调、智能体切换、权限、草稿、手机布局。
4. 精确提交工作流验证、候选部署和实际QQ/App/设备验收。

工作记录见worklog.md；交接见handoff.md。任何尚未完成项目明确列出，不以容器健康替代对话或真机验收。保留前面AstrBot未提交改动和用户附件。
