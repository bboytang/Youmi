# 步骤 3C：反思生成与完成回合驱动的维护调度

实施前计划，2026-10-26。

1. 按 owner 持久化反思开关、维护间隔、配置版本和最近成功整理的来源签名。默认关闭，间隔默认 24 小时，可调 60 秒至 7 天；不修改线上配置。
2. 使用既有成功完成回合的 JobStore/MemoryWorker，不创建额外模型队列或调用。任务入队时固定反思策略版本并争用每 owner 一个维护名额；到期后下一次成功对话触发维护，没有新对话时不发起空闲模型请求。新事实、明确修订仍逐回合处理，不受维护间隔或认知截断。
3. 既有 LLMMemoryExtractor 在启用模式输出 reflection_version=1 动作契约；同时支持已审阅工具流及旧 provider 的 JSON 路径。使用相同 provider factory、SDK/HTTP 请求账本、前台优先槽位、两次请求上限和完成提交事务。明确纠错快速路径继续免模型调用。
4. 只有维护到期时才向模型提供画像/笔记/退役及合并预览动作；不改动或删除事实。来源不变时不重复维护；配置变更、撤权、来源过时、过期、失败和重启必须正确取消、释放或恢复名额。失败不推进最近成功时间。模型不能控制调度、配置、版本或情感/人设。
5. 增加 V13，冻结 V1–V12，同步历史夹具和安装载荷。测试真实 SQLite、固定 SDK + MockTransport、重试、取消、故障与源版本；CI 验证准确提交。没有真实模型质量或真实终端证据时明确记录，不提前切换生产或默认召回。

这次的“定期”是成功完成回合驱动的到期维护，不是夜间无对话模型唤醒。与后续完整新引擎切换、情感联动、持久化索引恢复、管理页和真实质量评估分别验收。
