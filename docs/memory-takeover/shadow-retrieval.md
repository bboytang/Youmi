# 步骤 2A：只读仓储与天使之魂检索核心

这是步骤 2 的第一个子步骤；不是完整引擎接管。当前仅提供内部显式影子查询，未接入正式回复，未变更 schema、配置开关或情感表。

## 已实现的路径

`YoumiMemoryRuntime.shadow_retrieve(scope, authorization, query, use_vectors=True)`：

1. `YoumiMemoryRepository` 以独立只读 SQLite 连接捕获 owner、persona、确认/有效状态及内容/证据版本。鉴权前后复核，不创建新 owner。
2. 从该 owner 的快照构建临时 RAM Tantivy 索引。中文 CJK 分词、BM25 严格/宽松分阶段搜索和 RRF 来自固定上游提交，变更与 GPLv3 许可见安装载荷中的 YOUMI_MEMORY_NOTICE.md、YOUMI_MEMORY_LICENSE。
3. 可选复用现有 BGE 的向量候选；向量不可用时明确标记并回退到 BM25。权限撤销、记忆版本变化不能被当作可降级错误。
4. 结果按 ID 回到权威库重新读取来源与证据版本，并再次核验权限和快照；删除、纠正或证据变化后的旧结果不能返回。
5. 返回 `shadow_only=true`、引擎标识、快照、检索/向量状态及最多 4 条带来源记录。正常 `retrieve` 继续委派旧引擎，没有自动调用影子路径。

此接口不增加 HTTP 路由，客户端和模型不能自行切换引擎。它不记录原始查询或持久化检索结果，不更新召回次数、情感、人物设定、认知状态或记忆强度。

## 边界与依赖

- corpus 上限 10000 条、文本合计 8 MiB；超限明确返回 unavailable 异常，不截取一部分冒充完整结果。这是当前影子阶段预算，不是生产容量结论。
- 向量候选最多 24 条，使用现有 0.35 语义下限；不复制上游不同维度的模型和向量文件。
- 内存索引 writer 单线程、15 MB heap；单运行时最多一个原生搜索；等待槽位 0.4 秒、原生等待 5 秒。取消/超时后槽位仍由未完成的原生任务占用，直到它真正结束。
- 每次重新构建索引并显式 reload，避免当前阶段引入持久化索引一致性和多 writer 问题；代价是不能据此宣称大数据量生产延迟合格。
- `requirements-memory-shadow.txt` 固定 Tantivy 0.25.1。默认回复不导入该模块，不要求新增依赖；需要影子评估时单独安装。完整安装器和离线升级/命名转换载荷包含源代码、依赖说明、许可与归属。
- 上游原版在 BM25 无结果时可能丢弃已有向量候选；适配版保留经过语义下限筛选的纯向量候选。融合分数相同按 ID 确定排序。索引/查询异常明确报 unavailable，不伪装成无匹配。

## 验证方法

新增 17 项真实 SQLite / 原生 Tantivy 测试，覆盖原始 ID/来源/版本、同文本跨 owner、公有 scope 排除、待确认/失效排除、修正及删除使旧快照失效、资源上限、撤权、中文/全角/标点、纯向量候选、向量未就绪回退、重开数据库、查询中删除/撤权、情感及默认上下文不变、取消原生任务的并发限制、独立安装与许可。

Python 3.10/3.12 专用 CI 安装可选依赖并运行这些测试；完整服务器 CI 也安装此依赖。未安装时原生测试明确 skip，不能作为原生通过证据。

真实向量工作流增加 `verify_youmi_memory_shadow.py`：在实际安装包和固定 BGE 模型上，以无网络、CPU 2 / RAM 2 GiB 容器运行小型合成语料，验证 BM25、融合、权限边界、来源、纠正失效，以及旧引擎与全部 51 维情感不变。结果 artifact 为 memory-shadow-results.json；这仍是机制验证，不是独立质量对照或生产容量评测。
