## 范围与取舍

6A 只实现内部显式影子评估的可重建磁盘 BM25 缓存，不启用生产、不改变正常 retrieve。调用方需显式提供专用 shadow_cache_dir；不提供时继续原 RAM 路径。SQLite canonical 是唯一事实权威，向量仍由既有 SemanticMemoryIndex 维护，不另存向量或引入模型请求。

每次影子查询仍捕获完整授权 owner 快照（10000 条/8 MiB 上限），比较索引指纹后同步。新增记录增量添加；正文/检索元数据变更或记录移除时重建该 owner 的派生索引，避免旧分词残留在历史段文件中。新佐证不改变检索文本时无需重写 BM25，返回的来源/版本仍从 canonical 当场读取。

本阶段采用完整有界快照与指纹对账，不新增 outbox/schema：能够从当前事实重建时，不依赖所有历史写入路径逐一发布事件。代价是每次仍扫描和比较完整语料，不能声称生产大容量性能达标。后续压力/质量对照若不达标，再以证据决定 outbox，而不是提前修改冻结的 V1–V14。

## 一致性与恢复

- 按数据库绝对路径、owner、persona 的哈希分目录，不接受客户端路径或模型参数；目录私有，清单只保存版本/ID/文本指纹，不保存查询、来源摘录、历史情绪、角色人设或第二份事实 JSON。Tantivy 文件仍含私人分词，不能当作非敏感日志。
- 进程内保留原生单任务槽和取消后直到实际结束才释放的规则；同一磁盘分区使用跨进程文件锁，有限等待，锁住同步与搜索全过程，禁止两个 writer 并行。
- 同步前持久化 dirty 标记；Tantivy commit/reload 成功后原子替换并 fsync 清单，最后清除标记。进程中断、清单缺失/损坏/格式不符、索引丢失或无法打开时从当前 canonical 快照重建，不沿用不确定缓存。
- 磁盘失败明确报 unavailable，不当成无结果、不改变正常回复/情感路径。读取结束再次核验权限和 canonical 版本；并发修改或撤权不能返回旧结果。
- 无有效记录或显式影子查询发现召回关闭时，同步空索引，清除该分区已有分词。没有显式查询时不启动后台任务。

## 数据生命周期与启用限制

该模式目前仅供合成数据离线评估。缓存只在显式影子调用时对账，**不会在 canonical 删除完成的一刻同步擦除闲置磁盘缓存**。因此不能用于生产私有数据，更不能据此宣称线上遗忘已覆盖缓存。后续切换前必须接入完成写事务的失效/清理、服务启动恢复及明确的派生目录生命周期，验收跨进程删除、清空和磁盘数据保留策略。停止评估后由调用方移除其专用临时目录，不能放入备份或公开 artifact。

## 6A 第二段实施顺序（2026-10-26，先于代码）

第二段先交付可独立验证的 V15 事务失效账本，再接受控目录与清理执行器。当前写入来自 legacy store、worker 及不同进程，单个进程的 after-write 回调不能保证中断后恢复，因此采用 SQLite 触发器与事实同事务登记，不改 V1–V14。此次只交付账本基础，不宣称即时磁盘删除已实现。

- 每 owner 保留一行 generation/cleaned_generation；不存路径、正文、来源、查询或情绪。当前唯一合法 persona 仍为历史 `mia`；以后扩展 persona 前须重新评审分区键。
- 首次升级为已有 owner 登记待清理，之后内容 epoch、owner revision/paused 变化登记下一代。这些既有版本变化覆盖合法新增/修正/佐证/删除/待确认/退役/清空与召回设置写入；重复事件合并为一行，不保存无界事件列表。
- 读取待处理记录有界；内部清理器必须先完成所有已注册分区的物理清理，才可按读取的 generation 做 CAS 确认。期间有新写入时旧确认失败，不吞掉新任务。清理失败或进程中断不确认；重启仍可读取待处理代次。
- 此内部账本没有 HTTP/模型接口、路径注册或自动确认。现有合成缓存不读取/确认它，正常回复及情感完成不依赖磁盘清理。后续目录注册、跨进程搜索/删除锁序、成功响应语义、失败可见性和启动重试必须另行实现验收。

验收：真实 SQLite 同事务提交/回滚、独立写进程退出、两进程旧代次确认竞争、owner 隔离、重复写无界增长防护、源撤回/元数据/暂停/清空/功能开关、V14 升级值保持及幂等、迁移中断/失败回滚、冻结 V14 loader 拒绝 V15。安装载荷与历史夹具随 V15 更新，GitHub Actions 验证准确提交。完成账本后仍保持生产禁用。

## 6A 受控生命周期实施契约（2026-10-26，先于代码）

本轮新增 V16 注册表及内部受控影子模式，默认关闭，原合成缓存路径模式保留。每个 canonical 文件只使用其同目录的固定私有缓存根，不接受 HTTP/模型/调用者传入任意清理路径；分区继续由数据库绝对路径/owner/历史persona mia哈希生成。注册必须经过现有仓储授权，注册表不随owner删除级联消失，以便清理孤立分区。数据库搬迁前必须清空原受控根；数据库单独复制不证明旧位置已清理。

同一稳定 writer.lock 保留，清理只移除其余分区内容（含未知历史文件），fsync后才确认V15代次。不移除或替换锁文件/锁目录；拒绝符号链接根/分区/锁，不跟随索引内链接清理其他目录。SQLite事务不持有写锁等待文件锁；清理持文件锁后用独立连接做短事务确认。内置MemoryStore在事实事务成功提交后尝试处理已注册待清理分区，锁忙不等待，不回滚或阻断情感提交；未注册时不访问缓存文件系统。原始外部sqlite写入不保证提交时回调，仍由账本/启动恢复/后续查询清理，不作为立即遗忘支持入口。

受控影子查询先授权/注册，持同一文件锁时再次核对canonical版本才写索引；查询结束再次核对，期间有修改则清掉刚写的分区并拒绝结果，防止旧快照复活。清理失败/锁忙保留待处理代次与可查询错误类别，不能报物理清理完成；新写入使旧代次确认失败。已有注册在MemoryStore启动时恢复，后续提交和显式恢复重试，分批有界扫描并轮换游标避免一个失败owner遮住后面的分区。没有空闲模型请求、无界线程或默认引擎切换。

内部状态区分not_registered/complete/pending，pending表示事实可能已经提交但派生清理未完成；该状态不是事实写入回滚。管理接口追加此状态，不把待清理写成已清理；前端启用/真实终端展示仍须在生产切换验收时验证。正常回复继续旧引擎，生产不注册、不部署、不创建缓存。

验收：真实SQLite/Tantivy首次授权/分区隔离、修改/删除/空清空的提交后清理、失败事务不清、跨进程写入、查询中删除不复活、真实进程中断/重开恢复、稳定锁与忙态重试、删除/fsync/确认失败、孤立owner、符号链接拒绝、默认无目录/无模型/51维情感保持；V15升级/失败与中断、安装载荷和准确提交GitHub Actions。V1–V15保持冻结。
