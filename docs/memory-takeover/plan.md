# Youmi 记忆系统移植与情感联动方案

日期：2026-10-25。用户已要求开始实施，并要求每完成一步更新工作记录与交接。当前阶段和验证结果以 worklog.md、handoff.md 为准，不能把本方案当作完成证明。

## 目标与不可破坏的契约

移植天使之魂的反思、记忆修订、混合检索、画像、笔记和定期整理能力，形成后端统一的 `YoumiMemoryRuntime`，逐步替代现有记忆算法。App、设备、QQ 不各建一套记忆。

- 服务端鉴权产生 `user:<user_id>:agent:<agent_id>`；同智能体跨端共享，不同智能体的记忆、画像、笔记、索引、维护及情感严格隔离。
- 现有 51 维情感系统是情感状态的唯一权威，保留全部数值、模式、配置、恢复和管理功能；迁移不得重置。
- 完整人设原文保持可编辑，不能由反思、画像或上游四维状态改写，也不能被当作真实用户经历。
- 保留原始记忆 ID、来源证据、修订、待确认和删除状态。confirmed 不等于上游永久记忆标记。
- 现有鉴权、完成对话协议、来源校验和任务幂等设施继续使用；只提交成功完成且授权有效的对话产生的记忆和情感变化。
- 新业务代码、页面和接口统一 Youmi 命名。历史持久化标识及协议保持兼容，不作字符串式重命名。
- 保留工作区已有用户修改。不新增生产数据库或密钥备份，不发送未经授权的测试消息。
- 情感兼容、迁移和回退未通过验收，不切换生产。

## 上游基线及适配边界

上游：kawayiYokami/astrbot_plugin_angel_memory，版本 1.6.14，固定提交 `17454a12669c9a7f0f2e2fbe6a424f6f8f4fffe5`。

研究已验证：55 项选定上游测试、14 项研究用例通过，其中 11 项在现用后端镜像 Python 3.10 离线隔离容器复跑通过。这不是产品验收，也不证明召回质量优于旧系统。

必须改造：默认私有 scope 混入 public；按 ID 写入依赖调用方验证目标；原生写入缺少完成回合幂等；更新可能替换 ID；reasoning 不等于来源证据；SQL 路径未保存 state_snapshot；SoulState 状态未自动持久化；索引提交后有可见性延迟；部分导入按 judgment 而不是 owner+ID 去重。

核心移入后端进程，使用同一权威 SQLite 数据库和增量扩展表；向量/BM25 为可重建派生索引。禁止原插件数据库与现有数据库并行成为两个权威。AstrBot 事件、provider 和页面依赖改接 Youmi。管理页复用现有 Vue2/ElementUI 风格。

上游为 GPLv3，Youmi 为 MIT；实际复制代码须保留上游许可、来源、提交和修改说明，发布前确认对应分发义务。不能将复制代码改标 MIT。第一步兼容入口不复制上游实现。

## 双向情感联动

流程：读取人设与情感状态 → 召回相关记忆 → 评价本轮情感变化 → 生成回复 → 完成成功后提交情感并安排记忆任务。

- 记忆影响情感：只使用当前 owner 下有效、相关、可使用的记忆，提案引用记忆 ID、内容版本及证据片段。
- 情感影响召回：仅在相关性合格的候选中调整顺序，不修改事实，不覆盖否定、时间、纠错和固定条目规则。
- 记忆保存事件当时的情绪快照；无历史快照标记未知，不倒推生成。历史情绪不等于当前状态。
- 当轮原话与记忆证据分开标记，合并后只进行一次敏感度、固定/锁定、限幅和恢复计算。
- 保留旧情感提案格式，新增版本化内部格式。不能把记忆拼入当轮用户原话，绕过现有 quote 校验。
- 同一记忆版本在冷却期内不重复产生记忆刺激；用户本轮新的真实表达仍可正常引起变化。
- 记忆检索、索引或反思失败不阻断既有情感流程；情感评价失败保留当前状态并继续正常回复。授权错误不降级成成功。
- 现有单轮提案最多 8 个维度的边界保持不变；所有 51 维仍可被配置和选择。过时版本拒绝，不覆盖后台新设置。

按智能体配置：联动双向开关默认启用但继承现有总开关；记忆刺激权重默认 0.25；情感排序影响上限默认 10%；同记忆版本刺激冷却默认 24 小时。以上均可调。联动不能提高单轮最大变化或改写固定/锁定值。

四维认知 recall/impression/expression/creativity 独立持久化、可调，只控制认知策略，不能直接写情感表。明确纠错、遗忘和固定条目不受 impression 截断影响。

## 接口与页面

统一运行时先承接现有 ContextBuilder 使用的召回及快照校验接口，保持结果和异常契约；后续加入记忆动作提案、提交、画像、笔记、维护接口。第一步只委派现有算法，不宣称已完成上游移植。

管理端保留人设编辑及 `/agent/{agentId}/affect-system`，增加带版本检查的记忆联动配置。记忆系统提供独立入口，按智能体管理记忆、来源、修订关系、画像、笔记、固定条目和退役候选。情感变化记录可关联触发记忆及未生效原因。

保留当前历史容量限制，不默认额外保存聊天全文。自动衰减/退役初期只生成候选，用户在后台启用后才可执行删除。

## 验证策略

先使用真实 MemoryStore、SemanticMemoryIndex 和合成来源验证兼容，不用仅镜像实现的 mock 测试代替行为验证。覆盖不同 owner、来源、确认/删除、修订版本、功能关闭、权限撤销、失败与重试。

情感测试覆盖全部 51 维配置读写及上下文表达；固定/锁定、动态变化/恢复/限幅、设置版本冲突、记忆失败、重启和回退。上下文断言是主要证据，模型口头说“有情绪”不算通过。

中文评估涵盖关键词、语义改写、否定、纠错、时间变化、无答案和跨智能体负例。相同模型/预算下对照旧基线；纠错与隔离负例必须全部通过，其他质量不得低于基线，不能超过现有请求预算。

每步运行相关测试并检查 diff；产品提交推送后在 GitHub Actions 验证准确 SHA，工作记录填入结果和链接。后台 UI、真实 QQ/App/设备及物理硬件验收分开报告，不能把编译或容器健康当作真实对话通过。
